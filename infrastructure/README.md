# Synora infrastructure foundation (Issue #5)

Status: local/CI foundation; deployment proposals are inert. No cloud provisioning, migration, billing, or production changes authorized. All file paths here are DevOps-owned; no root/shared contract edits.

## Local development
Use Python 3.12, Node 22 LTS, Docker Engine with Compose v2 and Git. From repo root set SYNORA_LOCAL_DB_PASSWORD to a newly generated local-only password (PowerShell: $env:SYNORA_LOCAL_DB_PASSWORD = [guid]::NewGuid().ToString(); POSIX: export SYNORA_LOCAL_DB_PASSWORD="$(openssl rand -hex 24)"). Do not persist secrets in tracked files.
- docker compose -f infrastructure/compose.yaml config --quiet
- docker compose -f infrastructure/compose.yaml up -d --wait
- docker compose -f infrastructure/compose.yaml down (preserves data)
- python -m unittest discover -s infrastructure/tests -v

Compose is a disposable PostgreSQL 17.6 SQL-only development fixture, not Supabase Auth or a full RLS acceptance environment. Use a reviewed/pinned Supabase CLI with Docker for local Auth, Storage and RLS once backend supplies supabase/config.toml and migrations. Run supabase start only in the isolated Synora checkout; verify local status before resets. Never link an unrelated remote project. Use explicit Synora-only names, separate credentials, and never run remote db push or reset from CI. Local generated audio belongs in a private ignored directory outside the source tree.

## Health, rollback and monitoring
GET /health checks process liveness without touching dependencies; /ready returns non-2xx if required DB/storage/auth setup unavailable. No secret or internal details in response. Render uses /ready; verify both plus auth, signed URL range playback and failure/cancel behavior on approved staging. Track deploy commit, DB migration compatibility, backup and restore test, baseline p95 API latency, queue age, lease expiry, retries, error rate, storage growth and reserved vs settled spend. Alert on sustained readiness failures, backlog older than SLA, any budget overrun or repeated lease failures; thresholds initially proposed p95 >1s for non-generation API, oldest queued >5min, error rate >2% over 5min. Never ping free Render to evade sleep. Rollback: stop new admissions, pause dispatch, retain job state, roll back to last tested deployment ID in Render/Vercel, verify readiness and smoke tests, reconcile pending jobs. Migrations must be expand/contract and backward compatible; don't blindly reverse destructive migrations. Restore only approved Synora-specific backup to isolated target and verify before switching traffic.

## Private media and security
Require verified bearer token issuer/audience/signature/expiry; derive ownership from trusted subject, not request body. Enforce owner-scoped RLS and explicit grants, private bucket and DB queue not publicly writable; test two users and anonymous denial. Verify ownership before short-lived (proposed 300s) presigned GET; opaque object keys scoped by environment and asset ID; don't put signed URLs in logs. R2 candidate: private bucket, no public domain, per-bucket restricted S3 token, browser CORS explicit trusted origins, no wildcard with credentials. Direct uploads require bounded presigned PUT plus server verification, not trust client metadata; quarantine, inspect magic bytes, decode in sandbox, enforce byte/pixel/duration limits, reject archives and unexpected formats, strip metadata when appropriate, avoid arbitrary remote URLs/SSRF, malware scan and delete invalid objects. Never serve untrusted active content inline. HTTPS, exact CORS origins, rate limits, request IDs, redacted logs, no secrets in Git or build context. Require rights and voice/likeness consent. Supabase local and hosted policies must be separately tested, including service role bypass risks.

## Durable GPU design
Postgres is job truth. API commits reservation and queued job atomically before dispatch; external wakeup after commit, with independent reconciler to recover lost wakeups. A reliable scheduler/worker must be separately approved before real mode. Free Render is never the scheduler, and local fixture worker is explicitly manual. Select one candidate after music agent verifies model/license/VRAM and benchmarks. RunPod Flex workers min 0 max 1, or Modal min_containers=0 max_containers=1; model cache on separate bounded volume only after approval. Use immutable model revision and image digest. Per-attempt lease/fencing token, bounded timeout, idempotent provider submission or reconcile unknown outcome before retry, private upload then transactional success. Expired worker cannot overwrite new attempt. Authenticate callbacks, bind to job/attempt, replay protect. Cancellation is best effort upstream and must settle actual charges. GPU provider outage must stay a visible failed/queued state, never substitute mock. Cold start, cache download, idle grace, CPU/memory, storage, retries and transfer all count in cost estimate. No long-lived GPU allocation.

## Spending safeguards
Default policy is real generation disabled, budget zero, GPU concurrency zero. budget.py is a tested pure preflight, not authoritative enforcement; backend must implement transactional reservation/settlement in Postgres with idempotency and concurrency lock, per-user daily quota, global daily/monthly cap, provider timeout and retry bound. Reject unknown prices and estimates above caps, reserve worst-case cost including retries, reconcile provider charges, stop admitting on stale billing or unsettled reservations. Set provider hard spend cap where supported; alerts are not hard caps. No provider tokens or paid resources until owner approves an explicit budget. No claim that free credits eliminate costs.
