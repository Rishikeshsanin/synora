# Offline advertising prototype (Issue #4)

Local trusted CLI only, not a service. No API credentials, provider calls, shared M1 edits or deployment. Run from repository root, ideally Python 3.12 (local benchmark used 3.13.5; 3.12 still needs verification), with FFmpeg and ffprobe on PATH:

    python -m pip install -r engines/media/requirements.txt
    python -m benchmarks.media.demo /tmp/synora-ad-demo

Use a fresh output directory. Produces three original fictional product illustrations (not real photos), synthetic click audio, a JSON storyboard, approval digest, three MP4s and results.json. All fixtures generated by code specifically for this test; no third-party media. Demo approval is automatic and explicitly simulated. Real human approval is required outside the demo. Use a trusted local path only. The digest detects accidental storyboard changes, not authorization or proof of consent.

    python -m engines.media.render BOARD_JSON APPROVAL_DIGEST AUDIO_PATH 9:16 OUTPUT.mp4

Concept ranking: equal base score 3; add 2 for primary goal/platform/occasion match; add 1 for audience, industry or emotion match as appropriate. Stable tie break by ID. Three templates, not a learned recommender. Palette/dimensions/hash are real image analysis; no semantic identification, OCR or logo detection. Source is resized proportionally and fully contained, with caption outside it. Hard cuts every four detected beats and gentle scale animation. No invented factual copy: only supplied captions, but human review of claims remains mandatory. No semantic claims verifier. No paid calls ($0 API spend). No voiceover, background removal, real video synthesis or actual music generation. ASCII single-line captions only. Output resolution is preview quality.

## Proposal (not ratified)

Brief: audience, occasion, goal, industry, emotion, platform, verified product/business facts with evidence IDs, brand assets with consent and rights. Concept: stable ID, score/rationale, music direction, visual direction and proposed scenes. Board: version, ordered scene IDs, asset refs and hashes, explicit approved caption, timing in frames/beats, aspect ratio, soundtrack reference. Render approval in production must bind immutable board revision, soundtrack and voiceover hashes, target ratio, reviewer identity and evidence-backed claims; current local digest binds board only. Do not accept client paths, rights flags, or digest as authorization on server. Resolve authorized M1 asset IDs to local private staged files; reuse M1 job/asset lifecycle only after lead approval. Remotion adapter can translate frame edges to Sequence from/durationInFrames at 24fps; no Remotion runtime implemented. Proposed media provider interfaces: analyze(asset)->observations+confidence+evidence; generate_scene(approved_scene, context)->artifact+provenance+cost; voiceover(approved_script, consent, context)->audio; remove_background(asset)->mask+QC; render(approved_board, resolved_assets)->video+manifest. Every operation bounded, idempotent, budget-reserved and capability-gated. Granular regeneration uses scene content hashes + provider revision + seed + input hashes; changing a scene invalidates its cache and final composition; soundtrack change invalidates timing/composition, voiceover change invalidates mix/captions. Require renewed approval for changed publishable content.
